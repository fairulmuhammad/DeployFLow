# M1 — Identity and Tenancy

## Objective
Organizations are isolated by construction, proven by tests, before any tenant data exists.

## Read first
`docs/PRD.md` §3, `docs/DATA-MODEL.md` §4, `docs/SECURITY.md` §3–§4, `docs/API.md` §2–§3, ADR-015.

## Tasks
DF-005, DF-006, DF-007, DF-008.

## Create / touch
- Auth pages + controllers; verification, reset, profile, throttles.
- `app/Domain/Identity`, `app/Domain/Organizations`, `app/Domain/Audit`.
- `TenantContext`, `ResolveOrganization`, `EnsureRole`, `BelongsToOrganization` scope.
- Policies for every model that exists.
- Invitations with hashed tokens and expiry.
- Audit recorder + first audited actions.

## Contracts
Role matrix (PRD §3), invitation rules, `ERROR-CODES.md` auth codes.

## Exit proof
- `tests/Security/TenantIsolationTest` covers applications/environments/deployments/variables/logs/invitations (SEC-01…03, SEC-19).
- `AuthorizationMatrixTest`: every policy method allow + deny.
- Removing a member denies the next request immediately.
- Exactly-one-owner test; owner transfer updates both rows in one transaction.

## Guardrails
- No `withoutGlobalScope` outside the allowed list in `SECURITY.md` §3.
- No organization ID accepted from request input.
- Do not add a public API token mechanism.

## Handoff
Note any new invariant in `AGENTS.md` and add its test mapping to `SECURITY.md` §16.
