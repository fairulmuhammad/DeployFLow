# M5 — Deployment Engine

## Objective
Digest → active release, without ever risking the current one.

## Read first
`docs/STATE-MACHINES.md` §1, §3, §5; `docs/WORKER-CONTRACTS.md` §6–§13; `docs/SECURITY.md` §9; ADR-009, ADR-021, ADR-022.

## Tasks
DF-021, DF-022, DF-023 (a–d), DF-024, DF-025 (a–c).

## Create / touch
- `DeploymentStateMachine` + guards + events + outbox writes.
- Internal agent endpoints: start/step/config/heartbeat/complete/fail.
- `workers/deployment-agent/`: runtime adapter, container create, env tmpfs, health probe, Traefik file switch, cleanup.
- `ReleaseActivator` (single transaction, one-active index).
- Reaper extensions for deploy jobs and stuck deployments.

## Contracts
All deploy payload fields, container naming/labels/network, dynamic config path, step order.

## Exit proof
- PRD §9 steps 5–8 work end-to-end.
- FT-08, FT-09, FT-10, FT-12 pass.
- I-9/I-10 proven: failed health never switches; previous slot still serving after failure.
- No tag pull path; no arbitrary exec endpoint.
- Cancel pre-activation works; post-activation returns 409.

## Guardrails
- Never delete/deactivate the active release before the new one is verified.
- Never let the agent touch unlabelled containers or other environments.
- Do not trust log text for state.

## Handoff
Update `OPERATIONS.md` with the real switch/verification procedure and the slot retention default.
