# M2 — GitHub Integration

## Objective
Trusted events in, repository access known, nothing leaked to the browser.

## Read first
`docs/DATA-MODEL.md` §5, `docs/API.md` §4, `docs/SECURITY.md` §6, ADR-005.

## Tasks
DF-009, DF-010, DF-011.

## Create / touch
- `app/Infrastructure/GitHub/`: `GitHubAppClient`, `InstallationTokenProvider`, `WebhookVerifier`.
- Install/callback routes with signed single-use `state`.
- Webhook controller: raw-body HMAC, size cap, dedupe, persist-then-ack, outbox dispatch.
- `ProcessGithubWebhook` job; installation/repository lifecycle handling.
- Repository list/sync actions and pages.

## Contracts
Webhook headers and event set in `API.md` §4; table fields in `DATA-MODEL.md` §5.

## Exit proof
- SEC-05…07 pass with fixtures (valid, invalid, duplicate, wrong installation).
- A revoked installation blocks new deployments with `REPOSITORY_UNAVAILABLE`.
- Tokens/private keys never appear in responses, props, or logs.
- Verify during DF-009 whether GHCR push needs a dedicated token; record the answer in ADR-018 amendments if so.

## Guardrails
- Never trust repository names; validate IDs against the installation.
- No synchronous GitHub calls inside webhook handling.
- Do not log payloads or signature headers.

## Handoff
Document the GitHub App permission set actually configured in `CONFIGURATION.md` §5.
