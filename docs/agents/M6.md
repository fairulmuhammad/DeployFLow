# M6 — Logs, History, and Rollback

## Objective
A failure is explainable and recoverable from the UI alone.

## Read first
`docs/API.md` §5, `docs/UI-SPEC.md` §5.6, `docs/STATE-MACHINES.md` §5, ADR-014, ADR-019.

## Tasks
DF-026, DF-027, DF-028, DF-029.

## Create / touch
- History list/detail with steps and events; query-count tested.
- Log viewer: cursor pagination, signed URLs, step filter, follow mode (SSE optional).
- Rollback action creating a new deployment, digest reuse, health gate, audit.
- In-app notifications with per-deployment dedupe.

## Contracts
Log cursor/signing; rollback semantics; notification dedupe key.

## Exit proof
- FT-16/17 pass; rollback never rebuilds and never exposes an unverified release.
- A failed deployment is diagnosable from logs alone.
- SEC-13 and tenant denial on logs.
- One notification per failed deployment; read state persists.

## Guardrails
- Never render log content as HTML.
- Never return raw storage keys to the browser.
- Rollback must not delete the failed deployment.

## Handoff
Update `UI-SPEC.md` with the final empty/error states and `OPERATIONS.md` RB-06/07 if steps changed.
