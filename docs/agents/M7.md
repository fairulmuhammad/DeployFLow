# M7 — Hardening and Reliability

## Objective
Prove the platform fails safely under adversarial and broken conditions.

## Read first
`docs/TESTING.md` §6–§9, `docs/SECURITY.md` §16, `docs/OPERATIONS.md` §2–§3, ADR-016, ADR-020.

## Tasks
DF-030, DF-031, DF-032, DF-033.

## Create / touch
- Idempotency suite: deployment keys, webhook dedupe, outbox consumer, worker callbacks, concurrency.
- Failure-injection harness + FT-01…20 automation or scripted evidence.
- Structured logs with correlation fields; metrics; alert rules in `infrastructure/monitoring/`.
- Security review checklist; compose surface test; Trivy policy; dependency review.

## Exit proof
- SEC-01…20 and FT-01…20 green.
- Alerts fire in a staged drill (documented output).
- Build isolation limitations documented and accepted.
- No critical image/dependency findings without an accepted-risk ADR.

## Guardrails
- Do not weaken/delete a failing security test.
- Do not add retries that hide non-idempotent handlers.
- Do not silence alerts to get a green drill.

## Handoff
Update `SECURITY.md` §16 and `TESTING.md` matrices with actual test paths.
